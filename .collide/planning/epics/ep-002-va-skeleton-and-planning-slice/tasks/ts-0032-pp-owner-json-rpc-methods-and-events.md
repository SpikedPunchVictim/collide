## Goal

The JSON-RPC 2.0 contract between the UI or CLI and `collide-daemon` over the local socket: the envelope, the version handshake (`initialize` with the protocol version and the per-client token), the error codes, the event notification channel (each event carries a sequence number and the `actor` the daemon recorded), and the request and result types of the methods Milestones A and B need, grouped by family (`daemon.*`, `run.*`, `task.*`, `queue.*`, `workspace.*`, `config.*`; the `ask.*` family is `ts-0034-hh` and `ui_tools.*` is `ts-0035-re`). The plan does not list the methods, so this item derives the list from the CLI commands and the surfaces of 0.11 and records it in its Notes. The actor is never a parameter: it comes from the connection (0.2).

## Success criteria

- Serde round-trips pass for every request, result, error and event type.
- A request type with an `actor` field fails validation (unknown key), so no client can name its own actor.
- The handshake refuses a protocol-version mismatch with a message naming both versions, and a missing or wrong token with a distinct error.
- An unknown method answers the JSON-RPC "method not found" error.
- Every method in the recorded list has a request and a result schema, and `collide schema` lists them.

## Tests

Write first: round-trip tests; the `actor` refusal; handshake cases; one schema per recorded method.

- Area: `core` (types and schemas).
- Done when the criteria hold. Gap to report: the plan names no method list.
- Built: `core/src/owner.rs` and `core/src/owner/{daemon,board,task,run,queue,workspace,config}.rs`, pure types and checks with no I/O and no new dependency. The envelope (`Request`, `Response` as success or failure, `Notification`, `RequestId` as a number or a text, `JsonRpc2` that reads only `"2.0"`), newline-delimited framing (`parse_request`, `encode_line`, `MAX_MESSAGE_BYTES`), the handshake (`OwnerInitializeParams` and `OwnerInitializeResult`, `check_initialize`, `VersionRefused`, `tokens_match`), the error codes in one table (`code`, `CODES`), the one method list (`Method`, written by a macro that gives each method its name, family, `serves` text, request and result schema names, and a `normalize_params` and `normalize_result` that read a value as the type and write it back), `route` (unknown method, second or missing `initialize`, an `actor` key, bad params), and `Notice` (`daemon.event` carrying the store's `Event` with its `seq` and the recorded `actor`, `run.output`, `run.terminal_output`, `queue.changed`). Every request type has `deny_unknown_fields`, so an `actor` key is refused; `route` says the daemon takes the actor from the connection. Wire types stand in for the plain domain records (`RunSummary`, `PhaseSummary`, `WorkspaceSummary`, `TrustState`, `PhaseKindWire`, whose names a test pins to `PhaseKind::name`), because the records have no serde and the plan says this item fixes their wire form. Tests: `core/tests/owner_protocol.rs` (53, written first and red), plus two host tests (`collide schema` lists the envelope and every method type; every CLI command the daemon works for is served by a method). The roots are registered in `core/src/schema.rs`, and `pnpm gen` wrote 12 `Owner*` schema files and the TypeScript for each root (byte-stable on a second run).
- Methods (40, each with the CLI command or 0.11 surface it serves): daemon: `initialize` (0.2 handshake), `daemon.status` (0.2 health), `daemon.recapture_environment` (0.2 Recapture environment), `daemon.subscribe` (0.2 event channel, replay from a `seq`). board: `board.list` (switcher), `board.open` (0.11 no-setup open and first-run checks), `board.init` (starter files, dry run), `board.trust` (0.9 Trust by hash). task: `task.list` (`collide tasks`), `task.get` (`collide task`), `task.apply` (`collide task` with an op), `task.preview` (the op's files before it is applied), `task.views` and `task.save_view` (0.11 views), `task.sections` (`collide sections`). run: `run.start` (`collide run`, Launch), `run.preview` (0.11 run preview, same request type as `run.start`), `run.list` and `run.get` (Tracks, reattach after a restart), `run.stop` (`collide stop`), `run.diff` (Review), `run.output` (Agent output), `run.intervene` (a note to a running phase), and the take-over's `run.take_over`, `run.terminal_input`, `run.terminal_resize`, `run.detach`, `run.end_take_over` (0.11 Talking to an agent). queue: `queue.list`, `queue.context` (returns the existing `ContextRecord`), `queue.answer` (allow or deny, proceed, stop, retry, raise cap, accept, discard, re-prompt, text, acknowledge, resume, dismiss). workspace: `workspace.list`, `workspace.remove`, `workspace.resume` (0.8 Workspace). config: `config.get`, `config.set` (`collide config`), `config.pack_list`, `config.pack_add`, `config.pack_link`, `config.pack_enable` (`collide pack`). Left out: `collide schema` (reads the compiled contract) and `collide report` (the hook's own channel to its run); `run.spans`, metrics and compare (9c, 13); experiments (14); a `task.reid` (it is the provider op `reid` through `task.apply`); `ask.*` and `ui_tools.*` (ts-0034-hh, ts-0035-re; both answer -32601 here and a test says so).
- Decisions for the owner: (1) A `board.*` family, which the plan does not name: 6a's open with no setup, the board switcher and Trust need methods the six named families lack, and a board is the key most requests carry. (2) The plan has no accept or discard command and review is a Queue item, so accept, discard and re-prompt are answers of `queue.answer` and not `run.*` methods. (3) Framing is newline-delimited JSON with an 8 MiB cap per line; the plan sets neither. (4) Protocol version is the integer 1 and any other value is refused; the token is optional on the wire so a missing one gets the token error (-32004) and not a params error, and the token is checked before the version so an unauthenticated peer learns no version. (5) Codes: -32001 not initialized, -32002 already initialized, -32003 version, -32004 token, -32005 not permitted, -32010 not found, -32011 conflict, -32012 unavailable. (6) Every byte string (terminal input, output and replay) is base64, because terminal bytes are not always UTF-8. (7) A new session or a Plan session is `run.start` with `mode: interactive`, and the caller makes the scratch task or draft proposal first with `task.apply`. (8) The wire types duplicate the domain records' fields, so a change to `Run`, `PhaseRun` or `Workspace` needs the same change here; the alternative is serde on the records, which the plan's tagged-stub rule leaves open.
- Not done by design: the socket server, the actor from peer credentials and the person-only refusal (Stage 3a, ts-0033-zj; `code::NOT_PERMITTED` exists and nothing yet returns it); any method body; `ask.*` and `ui_tools.*`; the normalized agent-event wire (ts-0036-xt owns `AgentEvent`, which `run.output` carries as it is); and any change to the item's `status`, `links` or `owners`.
