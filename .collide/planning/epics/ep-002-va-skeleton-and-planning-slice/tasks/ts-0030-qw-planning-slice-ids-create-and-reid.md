## Goal

The `create` op and the id rules, through the provider and the CLI (`collide task create`). `create` writes `<id>-<slug>.md` into the epic's `tasks/` folder (an epic into `epics/ep-NNN-xx-<slug>/epic.md`). The slug is the first six words of the title, as in the existing item files. The number is the next free one for the kind across every ref Collide can see, local branches and fetched remotes. The suffix is two letters, never `i`, `l` or `o`, drawn from a seeded generator (the seed is an argument, random by default). A drawn id that is taken is redrawn until it is free among every ref. `collide task reid <id>` gives an item a new suffix, rewrites the links that name it, and commits nothing.

## Success criteria

- The number is the next free one across refs, including a branch that exists only as a fetched remote ref.
- A fixed seed gives a pinned suffix sequence, and a test fails if the generator changes.
- A forced collision (the generator rigged to return a taken id first) is redrawn.
- Two branches that each create number 12 with different suffixes both load, and `collide task 12` lists both.
- Two files with one id: the second is a `task.invalid`, and `collide task reid` on it gives it a new suffix, rewrites every link that names it, and leaves nothing committed.
- `create` returns the files it touched.

## Tests

Write first: id allocation over a fixture repo with a remote branch; the seeded suffix pin; the forced-collision redraw; the repeated number after a merge; `reid` rewriting links across several files.

- Number. Next free = highest number for the kind plus one, over `git for-each-ref` on `refs/heads` and `refs/remotes` (refs on one commit read once, `git ls-tree -r` of `.collide/planning/epics`) and the working tree. Ids are read from names on disk (`<id>-<slug>.md`, epic folders), nothing is opened. A root that is not a git repository is refused, because other branches could not be seen. A ref that only exists on a remote the clone has not fetched is invisible, as the plan says (two branches may still repeat a number; the suffix keeps the ids apart).
- Suffix. 23 letters (a to z without i, l, o), two draws per suffix from mulberry32 seeded with the `seed` argument (a fresh 32-bit random seed when it is left out). Pinned in `create.test.ts`: seed 1 gives `ra pz zg rt kz mn dk fd`, seed 42 gives `qm ws ep gr wm fx uh en`. Redraw: the number comes from the first look at the refs; each draw is checked against a fresh look (a fetch can land in between), and 5,000 draws without a free id stops with an error. Because the number is one past every visible number, a visible id is never drawn in practice; the redraw covers the id that appears between the looks, and `reid`, where the number is fixed. The forced-collision test rigs the generator and makes a ref appear after the first look (`IdHooks` in `ids.ts`, set only by tests).
- Slug. First six words of the title, lower case, joined by hyphens. A word is a run of ASCII letters and digits; an apostrophe is dropped inside a word, any other character ends it (`Collide's` is `collides`, `S5-S8` is two words, `exit.json` is `exit`). Checked against eight real titles and file names. A title with no such word gets `item`. Title limits: 1 to 200 characters, no control character, no space at either end.
- `create`. `id` and `version` are refused if sent (it makes the id). Args: `title` (required, the CLI's bare value), `epic` (full id; required for a task, refused for an epic), `kind` (`task` default, or `epic`), `seed`. The epic must exist in the working tree. The file starts with `status: ready`, `owners: []`, `links: []` and empty Goal, Success criteria, Tests and Notes sections, is written with the same temp, fsync, rename and directory fsync as the other writes under the same lock, is read back, and `files` holds its path (the new epic folder is not listed, only `epic.md`). The CLI resolves `epic=` through the short-id lookup (`2` and `ep-2` both mean `ep-002-bb`; a task is refused as an epic) before the provider sees it.
- `reid`. Which file: the provider renames the second file in scan order that has the id (the one the scan sets aside as `task.invalid`, the first in folder-then-name order is the item); with one file, that one; a third is reached by running it again. The CLI addresses it by the id alone (`collide task reid ts-0002-bb`), because the list holds only the first file; `collide task <id> reid` means the same. No `version`: the op rewrites several files, each read under the lock and checked against what the scan read, and a sent version is refused rather than ignored. Links: every `to:` that names the old id in the `links` lines of every item file that reads (one-line entries, block mappings, flow lists, quoted or not, comments and line endings kept); then the new content of every file is worked out and checked (re-parse, deep-equal, as `setStatus` does) before anything is written, so a link in a form the provider does not edit (for example `to: !!str ts-0002-bb`) refuses the whole op and writes nothing. Prose in a body that mentions the id is not a link and is not touched. A file's `epics/` folder name or item file name keeps what follows the id (`ts-0002-bb-two.md` becomes `ts-0002-ra-two.md`); an epic's whole folder is renamed. Order of writes: each file replaced in place (the renamed item's own file last), then the rename, so a kill between steps leaves every file whole, at worst a file name behind its id; there is no undo across files. `files` lists every file touched at its new path, and the old path of a renamed file (the CLI prints those as `removed`). Nothing is committed; a renamed file shows in `git status` as deleted plus untracked until it is added.
- Links meant for the other same-id file are rewritten too: the id cannot tell the two files apart, so every link that names it moves to the new id. To undo, take the new id off the links that were meant for the other file by hand: `git diff` lists each file the command printed, and `git checkout -- <file>` restores one (the renamed file is the untracked one; delete it and `git checkout -- <old path>`). Or run `git checkout -- .collide/planning` and `git clean -n .collide/planning` to review, then discard everything, before anything is committed.
- Exit codes and grammar are the ts-0020 ones: 0 ok, 1 failed, 2 wrong command line (a missing title, an unknown argument, `collide task <id> create`), 3 an id or epic names no item or several, 5 refused (a task with no epic, a bad title). `collide task <id> create` is refused with a pointer, and `create` is left out of the op list printed for an unknown op.
- Not done, by design: `--checkout` and `--commit` (ts-0031-xu; a non-null `checkout` is still refused); the full command tree (ts-0041-xf); an `alias` or other frontmatter at create time; `reid` of a file that is not the second of its id (no `path` argument; the second-in-scan-order rule covers the case the criterion names); renaming an epic folder that does not start with the epic's id leaves the folder as it is.
